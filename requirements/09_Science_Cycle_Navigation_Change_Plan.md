# 科学环入口改造方案 v0.1

## 1. 改造目标

将 P-Layer 从“打开即进入项目执行”改为“打开先进入科学思考”。用户不必一开始就拥有正式研究问题，可以从生活观察、模糊 Idea、文献或已有研究项目进入。

核心产品关系：

```text
科学环（总入口）
├── 头脑风暴：从好奇与观察开始
├── 文献网络：从阅读与怀疑开始
├── 重新检查：回到已有假设和证据
└── 研究项目：RQ 成熟后由用户主动进入
    ├── 项目开发
    ├── 看板
    └── 项目管理
```

## 2. 顶部导航改动

### 当前导航

```text
首页｜头脑风暴｜项目开发｜看板｜项目管理｜文献管理｜设置
```

### 建议导航

```text
科学环｜头脑风暴｜文献管理｜研究项目｜看板｜设置
```

### 具体变化

| 当前模块 | 处理方式 | 原因 |
|---|---|---|
| 首页 | 改名并改造成“科学环” | 首页不再只是快捷入口，而是产品的认知总入口 |
| 头脑风暴 | 保留 | 这是从模糊想法到 RQ 的核心路径 |
| 文献管理 | 保留 | 这是从文献进入科学环的另一条路径 |
| 项目开发 | 收入“研究项目” | 它服务于已经具备 RQ 的正式研究 |
| 看板 | 保留 | 用于任务和进度管理，不属于科学环本身 |
| 项目管理 | 与项目开发合并为“研究项目”入口 | 避免用户在两个项目模块之间困惑 |
| 设置 | 保留 | 账户、模型、本地数据和偏好设置 |

## 3. 科学环首页结构

页面分为四层：

1. 顶部品牌区：P-Layer、用户空间、设置；
2. 主标题区：解释“研究从好奇开始”；
3. 科学环区：展示观察、理论、假设/预测、证据之间的循环；
4. 入口区：头脑风暴、文献网络、继续探索、研究项目。

科学环不是一个必须按顺序完成的流程图。用户可以点击任意节点进入，也可以返回前面的节点重新思考。

### 理论层与实证层

科学环应呈现两层关系：左侧是理论研究与理论构建过程，右侧是实证研究与经验检验过程。P-Layer 当前的主要执行能力属于实证研究，例如假设、操作化、设计、数据和分析；但理论层仍然必须存在，因为用户需要理解概念从哪里来、命题如何形成、假设为何成立，以及证据如何反过来改变理论。

这不是两个互不相干的产品，也不是“理论在上、实证在下”的价值等级。它们之间应有往返连接：理论可以产生假设，经验概括可以推动概念和理论修正，实证结果也可以回到理论层重新解释。用户可以从任意位置进入，但进入后应继续完成至少半圈，形成一个局部的研究思考闭环。

四个固定节点作为两层之间的共同锚点：经验观察、理论与概念、假设与预测、证据与修正。四节点固定，节点内部的具体步骤可以根据用户进入的研究路径不同而变化。

科学环中心的主要动作应是“输入我的 Idea”，用于创建或开始一个新的研究想法，而不是直接进入 Idea 列表。已有 Idea 的查看和继续探索放在首页或科学环的次级入口中。中心可以保留一个不抢主动作的“查看已有 Idea”入口，但不能让用户误以为科学环中心只是资料库。

第一版理论侧只支持概念、理论、命题和逻辑推演的记录与连接，不实现独立的理论研究训练流程。理论研究能力可以在后续产品阶段继续定义。

用户从任意节点进入后，Pia! 可以显示建议继续的两个节点，帮助用户形成至少半圈的局部闭环；用户仍然可以离开、暂停、返回或选择其他节点。

用户完成当前理论或实证轨道后，Pia! 可以提示是否愿意继续另一条轨道。用户可以继续，也可以保存当前成果并离开。完成一条轨道是阶段性研究成果，但不等于一篇论文已经完成；不同论文类型需要不同的理论、问题和证据闭环。

科学环必须显示当前 Idea 已经走过的节点和当前所在节点，让用户看见自己的研究思考轨迹。

理论记录与实证记录默认归属于同一个 Idea。用户未来可以主动将它们拆分为两个新 Idea，但系统不自动拆分。用户只完成理论轨道时，也可以生成“理论研究构想”PDF，不要求先完成实证轨道。

双轨进度采用渐进显示：用户只进入一条轨道时，只显示当前轨道的节点和进度，不显示另一条轨道“尚未完成”。只有用户主动同时探索理论与实证两条轨道时，才显示双轨进度，例如“理论轨道 60%｜实证轨道 20%”。

用户点击并进入另一条轨道后，才算同时进入两条轨道，从这一刻开始显示双轨进度。RQ 阶段的理论研究构想 PDF 提供核心概念、理论依据、命题、逻辑推演和待验证问题。当理论与实证两条轨道都完成一部分后，用户可以选择生成合并两条轨道的“综合研究构想”PDF，但默认不要求合并，因为两条轨道通常具有不同的目的、读者和表达方式。

同一个 Idea 下，理论轨道和实证轨道可以分别形成各自的 RQ。Idea 是较宽的思考来源，一个 Idea 可以分支出多个研究问题；系统不应强迫两条轨道最后压缩成同一个 RQ。

RQ 采用 Idea 下的分支编号，例如：

```text
Idea-10：风浪与鱼价
├── Idea-10 / RQ-1：理论研究问题
└── Idea-10 / RQ-2：实证研究问题
```

理论 RQ 和实证 RQ 都可以各自生成独立的成果 PDF。某个 RQ 进入正式研究项目后，其他 RQ 是否继续留在原 Idea 下独立发展，由用户选择；系统不自动关闭、合并或迁移其他 RQ。

版本支持分层编号，例如 `Idea-10 / V5 / RQ-2 / V3`。RQ 拆分为新 Idea 时，保留“源自 Idea-10 / RQ-2”的溯源关系。

### 科学环的核心交互

科学环必须具有“从哪里进入，哪里聚焦”的动态行为：

1. 用户点击任意节点；
2. 科学环沿最短方向平滑旋转；
3. 被点击节点移动到最高点；
4. 被点击节点放大、提亮并显示简短说明；
5. 用户确认进入后，打开该节点对应的功能空间。

建议将“旋转聚焦”和“进入页面”分成两个短阶段，避免用户不知道自己为什么突然跳转。动画不能改变 Idea 数据或研究状态。

科学环的旋转不是游戏化奖励，而是把用户的入口位置转化为可理解的研究方向提示：从观察进入、从理论进入、从预测进入，或从证据修正进入。

## 4. 各入口的职责

### 头脑风暴

服务于：

```text
模糊 Idea → 命题 → 解释 → 预测 → 前提/边界 → 替代解释 → 证据 → RQ
```

### 文献网络

服务于：

```text
文献 → 理论/方法/证据 → 连接 Idea → 改变命题或预测 → 重新检查 RQ
```

一个 Idea 可以连接多篇文献，一篇文献也可以连接多个 Idea。文献相似关系与文献如何改变用户想法的关系必须区分。

### 研究项目

只有当 Idea 达到“可研究的 RQ”后，才显示“进入研究项目”的资格。用户自己决定是否进入，不自动跳转。

## 5. 对现有“项目开发”页面的处理

现有九步流程：

```text
研究问题 → 理论与假设 → 变量操作化 → 设计与功效
→ 预注册与伦理 → 平台与收集 → 数据结构与审计
→ 统计分析与解释 → 回到假设
```

不删除，但调整为“研究项目”内部流程。它不再承担新用户的第一次入口，也不再假设所有用户已经拥有成熟 RQ。

## 6. 用户完成 RQ 后的出口

用户形成 RQ 后显示可选出口：

- 生成成果 PDF；
- 继续连接文献；
- 请求反馈；
- 重新检查假设；
- 导入正式研究项目；
- 暂停并稍后继续。

系统不自动选择出口，不强迫用户进入项目。

## 7. v1 不做的事情

- 不在科学环首页展示复杂统计数据；
- 不把科学环变成九步项目执行清单；
- 不自动判定哪个入口更“正确”；
- 不把成熟度等级做成分数；
- 不在第一版实现团队协作权限；
- 不要求用户理解理论术语后才能开始。

## 8. 页面验收标准

用户第一次打开页面后，应该能够立刻理解：

1. 我可以从一个模糊想法开始；
2. 我也可以从一篇文献开始；
3. 这两条路径属于同一个科学循环；
4. 我可以随时返回和修改；
5. 形成 RQ 后，我自己决定下一步；
6. 正式项目是一个后续选择，不是起点。

## 9. 页面美学方向

### 方案 A：安静学术工作台

- 基础色：雾蓝、白、深靛蓝；
- 视觉感受：清楚、克制、可信、适合长期使用；
- 科学环：细线、圆形、低饱和节点；
- 入口卡片：像研究工作台的工具卡；
- 适合定位：学术训练、研究记录、长期知识系统。

### 方案 B：温暖科学旅程

- 基础色：米白、墨黑、珊瑚橙、青绿色；
- 视觉感受：好奇、亲近、有生命力、降低新手压力；
- 科学环：像一张可探索的地图，节点更有性格；
- 入口卡片：更像“从这里开始”的邀请；
- 适合定位：学术民主化、第一次研究体验、Pia! 教练品牌。

两个方案共用同一信息架构，差别只在视觉语言，不改变产品逻辑。

## 10. 五个核心入口的职责

### 首页：我的研究空间

首页不是科学环的重复版，而是用户登录后的个人状态页，回答：

> 我最近在研究什么？下一步可以继续什么？

建议内容：登录鼓励语、最近打开的 Idea、最近的文献、待处理反馈、最近生成的 PDF、继续上一次探索、进入科学环的快捷入口。

首页不展示完整的科学方法流程，也不要求用户在这里理解研究环节。

### 科学环：我的研究思考入口

科学环回答：

> 一个研究想法如何从观察、理论、预测和证据之间发展？

它提供头脑风暴、文献网络、重新检查假设和进入研究项目的入口。科学环是 P-Layer 的核心认知界面，不是任务清单。

### 项目管理：我的正式研究项目

项目管理只管理已经成立或准备成立的 Research Project，包括项目名称、RQ、版本、成员接口、研究阶段、归档和进入项目开发的入口。

它不承担最初的模糊 Idea，也不把所有用户都强迫变成项目。

### 看板：我的研究行动

看板回答：

> 我现在要做什么？做到哪里了？

它管理阅读、访谈、数据准备、实验、分析、反馈处理等可执行任务。看板是行动视图，不是研究思考视图。

### 设置：我的 P-Layer 环境

设置管理账户、个人资料、Pia! 偏好、本地模型、数据保存位置、导入导出、通知、隐私与删除选项。

## 11. 推荐导航

```text
首页｜科学环｜项目管理｜看板｜设置
```

头脑风暴和文献管理不必作为与科学环平行的一级导航，它们可以作为科学环的核心入口；如果用户频繁使用，也可以在科学环页面提供固定快捷入口。
