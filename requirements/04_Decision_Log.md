# P-layer 决策日志

| 编号 | 事项 | 状态 | 当前决定/假设 | 备注 |
|---|---|---|---|---|
| D-001 | Demo 标题 | 已知约定 | 使用“给 PINZHANG 的一句话 / A NOTE FOR PINZHANG” | 登录后切换为当前用户昵称 |
| D-002 | 寄语主题 | 已知约定 | 覆盖学术、公共/政治、商业/创造、品格、困难时刻 | 后续可按使用场景重组 |
| D-003 | 引语出处 | 已知约定 | 无法确认逐字出处时标为“思想启发/转述” | 不伪装成原文 |
| D-004 | 浏览去重 | 已知约定 | 同一轮不重复；换轮时重新随机且避开上一轮最后一条 | 需在实现时定义 session 边界 |
| D-005 | 首发核心价值 | 暂定 | 一句话触达 + 收藏/反思/行动入口 | 待用户访谈验证 |
| D-009 | 产品使命 | 已确认方向 | 学术民主化与学术平权：降低早期科研者获得研究训练、资源和机会的非必要门槛 | 这是产品信念，不等于对所有学术制度的经验性证明 |
| D-010 | 核心用户 | 暂定 | 多年 RA 但缺少独立资源者，以及没有 RA 机会却想进入科研者 | 需要进一步排序首发人群 |
| D-011 | 产品本体 | 已修订 | 首先是科研资源与研究能力工具层，不是寄语/情绪支持产品 | P Note 可作为辅助入口 |
| D-012 | 首发方向 | 待确认 | 优先在研究想法诊断、文献比较、项目路径三者中选一 | 需要根据用户痛点和实现成本决定 |
| D-013 | 个人版头脑风暴产出 | 已确认方向 | 形成由用户主导的初步 Research Question，不是自动生成最终 RQ | 每一步都要留下可回看的成果 |
| D-014 | 个人版十分钟目标 | 已确认方向 | 让用户从观察/疑问/直觉/批判形成命题、预测和初步 RQ | 先获得正反馈，再逐步增加严谨性 |
| D-015 | Pia! 介入方式 | 已确认方向 | 默认用户自主探索；用户主动求助、卡住或出现严重逻辑错误时才介入 | “没听懂”可触发分层解释 |
| D-016 | 学习错误记录 | 已确认方向 | 保存概念、逻辑、测量、范围和证据错误及其后续修正 | 作为个人科研学习记录，不作为惩罚 |
| D-017 | 十分钟成果形式 | 已确认方向 | 生成主要面向同学、导师、潜在合作者和反馈者分享的成果 PDF | 它是正式开题前的研究形成步骤，不是论文或成绩单 |
| D-018 | 科学环指导思路 | 已确认方向 | 以 Wallace 的科学环指导头脑风暴与文献管理；允许从观察或理论/文献等不同位置进入，并在归纳、演绎和证据修正之间循环 | 作为认知模型，不做成僵硬线性流程 |
| D-019 | 本地 Idea—文献网络 | 已确认方向 | 文献网络表达文献之间的关联强度；Idea—文献连线表达文献是否进入并改变用户的研究思路 | 先判断是否存在关系，再评价关系质量；连接来源必须可区分 |
| D-020 | 当前产品阶段 | 已确认方向 | 先做 Idea 记录、分类、用户主导的澄清润色、文献比较和文献发现；实验设计及数据分析属于后续阶段 | 先完成想法形成与知识连接，不把首发做成完整统计平台 |
| D-021 | Idea 定义 | 已确认方向 | 任何对用户有价值的好奇都可以成为 Idea，不要求一开始有学术价值或逻辑完整 | 先保存，再探索其是否能发展为公共研究价值 |
| D-022 | Idea 分类 | 已确认方向 | 按进入 Idea 的知识语境分类：学术理论、文献阅读、商业实践、生活观察、实验/数据 | 科学环位置和执行状态不作为分类标准 |
| D-023 | Idea 成熟度 | 已确认方向 | 用 I0–I6 表示从种子到可立项，文字与颜色并用；等级按成果条件判断，可跨级、降级和回退 | I5 可输出研究想法简报，I6 可建立研究项目 |
| D-024 | Idea 生命周期 | 已确认方向 | 成熟度与 Active、Paused、Archived/Abandoned、Converted 等生命周期状态分开 | 放弃不是删除或失败 |
| D-025 | Pia! 润色方式 | 已确认方向 | 采用用户主导的苏格拉底式诘问：澄清、检查前提、反例、替代解释、重新表达 | Pia! 不替用户决定 Idea 或 RQ |
| D-026 | 成熟度建议权 | 已确认方向 | Pia! 根据用户已完成的成果推荐成熟度等级，由用户确认；不干预用户的学术品位和追求 | 仅在推进为可分享 RQ 或正式项目时检查最低质量门槛 |
| D-027 | 最低 RQ 质量 | 已确认方向 | 初步 RQ 至少应达到可清楚讨论、可提出预测/探索路径、可继续连接证据的硕士论文级研究问题 | 用具体质量条件判断，不用学校名望作自动评分 |
| D-028 | 成熟度反馈呈现 | 已确认方向 | 同时展示当前等级、已完成成果和尚缺条件；用户确认，不把等级做成单一分数 | 反馈用于导航和学习，不用于评价用户天赋 |
| D-029 | RQ 后的第一步 | 已确认方向 | 形成初步 RQ 后先生成可分享 PDF，再进入文献管理深化 | 先给予用户成果和正反馈，文献用于后续校准与拓展 |
| D-030 | 分享版 PDF 的作者呈现 | 已确认方向 | 只展示用户自己的研究成果，不展示 Pia! 的提问、建议、成熟度判断或 AI 生成痕迹 | Pia! 是隐形教练，用户保留作者身份 |
| D-031 | 分享版 PDF 身份信息 | 已确认方向 | 显示用户姓名、昵称、生成日期和版本号 | 让成果具备可分享、可反馈和可继续发展的身份信息 |
| D-032 | PDF 前的用户控制 | 已确认方向 | 用户可逐项确认和手动修改，也可跳过 PDF，直接将初步 RQ 导入研究流程 | PDF 是可分享成果，不是强制门槛 |
| D-033 | Idea 成果重新生成 | 已确认方向 | 同一个 Idea 可以随时重新生成成果 | 版本历史的具体保留方式待进一步讨论 |
| D-034 | 分享反馈形式 | 已确认方向 | 反馈最小形式为直接文字输入，并可提供结构化提示提高反馈质量 | 反馈先回到 P-Layer，不自动改写用户 Idea |
| D-035 | 反馈采纳权 | 已确认方向 | 用户决定采纳、忽略反馈，或将反馈转成新的研究记录 | 外部反馈与用户原创内容分开保存 |
| D-036 | 反馈者身份 | 已确认方向 | 反馈者可以选择显示姓名/昵称或匿名 | 由反馈者自主选择 |
| D-037 | 反馈绑定关系 | 已确认方向 | 当前沟通流中的反馈绑定具体 PDF 版本；用户可之后归纳到某个 Idea 下 | 保留反馈发生时的版本语境 |
| D-038 | Pia! 处理反馈 | 已确认方向 | Pia! 可以整理、归纳和提炼反馈，但不替用户决定是否采纳 | 采纳权属于 Idea 作者 |
| D-039 | 多人反馈 | 已确认方向 | 同一份 PDF 可接受多位反馈者的独立反馈，支持邮件和 P-Layer 用户 | 反馈分别绑定同一 PDF 版本 |
| D-040 | 反馈可见性 | 已确认方向 | 个人版每人只能看到自己的反馈；团队版可选择共享给其他人 | 默认保护反馈者隐私 |
| D-041 | 连续讨论 | 后期功能 | 用户未来可以围绕 PDF 版本回复反馈者并形成连续讨论 | 当前阶段先实现独立文字反馈 |
| D-042 | 分享方式 | 已确认方向 | 支持专属反馈链接和公共区域分享；公共分享可以不插入专属反馈链接 | 适配定向反馈与公开展示两类场景 |
| D-043 | 反馈入口控制 | 已确认方向 | 用户可以随时关闭某一份 PDF 的反馈入口 | 关闭后不再接收新反馈，既有反馈保留 |
| D-044 | 新反馈提醒 | 后期基础能力 | 新反馈需要通知用户；当前先预留服务器、通知和数据结构，后期实现 | 不影响当前本地/静态成果闭环 |
| D-045 | 公共分享反馈权限 | 已确认方向 | 公共分享的 PDF 默认仅允许受邀且已注册的 P-Layer 用户反馈 | 保护作者成果与反馈质量，公共分享不等于匿名开放投稿 |
| D-046 | 反馈结构 | 已确认方向 | 反馈保留自由文字，并要求/提供反馈类型：表达不清、逻辑问题、理论建议、文献建议、研究价值、其他 | 让反馈可整理、可归纳，同时保留反馈者的开放表达 |
| D-047 | 反馈采纳后的归档 | 已确认方向 | 用户自行决定并记录反馈处理结果；默认归档为原 Idea 的修改记录，用户也可以选择转为新 Idea | Pia! 可提示和整理，但不自动修改或替用户决定 |
| D-048 | 反馈邀请入口 | 已确认方向 | 作者可以下载 PDF 作为邮件附件发送；教授等反馈者可以直接回复邮件，也可以使用反馈链接；使用 P-Layer 链接反馈必须注册 | 兼顾学术交流习惯与平台内可追踪反馈 |
| D-049 | 关闭反馈后的 PDF | 已确认方向 | 关闭某份 PDF 的反馈入口后，PDF 仍可被查看，但不再接受新的反馈 | 阅读权限与反馈权限分离 |
| D-050 | 多类型反馈 | 已确认方向 | 一条反馈可以同时选择多个反馈类型 | 允许反馈同时涉及表达、逻辑、理论等不同层面 |
| D-051 | 邮件反馈归档 | 已确认方向 | P-Layer 不读取用户邮箱，也不自动抓取教授回复；每份 PDF 使用专属编号，用户可根据编号手动复制或归档邮件反馈 | 降低权限和隐私风险，保留邮件交流习惯 |
| D-052 | 受邀注册邮箱 | 已确认方向 | 受邀者注册 P-Layer 时必须使用作者邀请的邮箱 | 让邀请权限与反馈者身份绑定 |
| D-053 | 反馈处理状态 | 已确认方向 | 用户可以手动标记反馈状态：未阅读、正在考虑、已采纳、暂不采纳、已转为新 Idea | 让外部反馈进入用户自己的研究判断流程 |
| D-054 | 邮件反馈导入 | 已确认方向 | 用户填写 PDF 专属编号后，可以直接复制并粘贴整段邮件对话；P-Layer 使用 7B 模型归纳反馈 | 不读取邮箱，降低权限要求，同时减少手动整理成本 |
| D-055 | 反馈处理理由 | 已确认方向 | 用户标记反馈为“已采纳”或“暂不采纳”时，鼓励但不强制填写理由 | 把外部意见转化为用户自己的学术判断训练 |
| D-056 | 反馈状态历史 | 已确认方向 | 保留反馈处理状态的完整变化记录，而非只显示当前状态 | 形成可回顾的判断轨迹，例如“未阅读→正在考虑→已采纳” |
| D-057 | 邮件原文保存 | 已确认方向 | 7B 归纳后仍保留完整原始邮件对话，供用户核查 | 摘要不是原文替代品，保留反馈语境与可追溯性 |
| D-058 | 反馈摘要编辑 | 已确认方向 | 用户可以手动修改 Pia!/7B 生成的反馈摘要后再保存 | 模型只提供初步整理，最终记录由用户确认 |
| D-059 | 本地模型隐私边界 | 已确认方向 | 本地 7B 模型默认不触发外部传输隐私警告；仍需考虑本机存储、日志和设备访问边界 | 本地处理降低外传风险，但不等于数据自动安全 |
| D-060 | 教练式自由度原则 | 已确认方向 | P-Layer 与 Pia! 优先保护用户的自主判断和选择权；结构化、提醒和建议都应可编辑、可跳过，不把教练变成管理者 | 只有影响边界、隐私、可追溯性或学习质量的事项才进入强制需求 |
| D-061 | 反馈摘要形式 | 已确认方向 | 反馈摘要可提供“核心意见、具体问题、建议方向、涉及类型”等结构化字段，但用户可以自由编辑、清空或改用自由文本 | 结构化是辅助阅读，不是限制表达 |
| D-062 | 模型不确定性 | 已确认方向 | 7B 无法确定反馈含义时，应温和提示“可能存在误解，请核对原文”，但不阻止用户保存 | 原文始终保留，最终判断属于用户 |
| D-063 | Pia! 的反馈建议 | 已确认方向 | Pia! 只在用户打开反馈整理、请求帮助或主动进入下一步时提出“归档为原 Idea/新 Idea”等建议，不主动替用户触发改变 | 建议可确认、可忽略、可修改 |
| D-064 | 反馈者修改权 | 已确认方向 | 反馈者可以自行修改或删除自己提交的反馈 | 用户拥有把事情搞砸的自由，平台不替用户维护一个不可更改的“正确版本” |
| D-065 | 作者删除权 | 已确认方向 | PDF 作者可以删除收到的反馈，也可以选择不采纳 | 删除权属于内容所有者，不强制把所有反馈永久保留在工作区 |
| D-066 | Idea 修改对照 | 已确认方向 | 用户采纳反馈并修改 Idea 后，保留修改前/修改后的对照记录 | 自由修改与过程可追溯性同时存在，便于回看和重新判断 |
| D-067 | 早期 Idea 分享 | 已确认方向 | 用户可以自行截图分享早期 Idea；P-Layer 不为尚未形成成果的 Idea 强行设计完整反馈闭环 | 早期分享保持轻量，正式反馈能力服务于可识别版本的成果 |
| D-068 | 反馈关注点 | 已确认方向 | 用户自己决定希望反馈者评价什么；Pia! 不替用户设定反馈目标或干预学术品位 | 用户保有提问权和学术追求 |
| D-069 | 反馈后的反思 | 已确认方向 | 收到反馈后，Pia! 可以提供可选的反馈反思协助，帮助用户理解反馈改变了原 Idea 的哪一部分 | Pia! 提供教练式支持，但用户自行判断和处理 |
| D-070 | 反馈反思保存 | 已确认方向 | Pia! 协助形成的反馈反思必须经用户确认后，才能保存到原 Idea | AI 生成内容不能未经确认成为用户的研究记录 |
| D-071 | 反馈分歧 | 已确认方向 | 多个反馈者意见不一致时，Pia! 可以指出存在不同观点，但不判断谁正确 | 把分歧保留为研究判断材料，而不是替用户裁决 |
| D-072 | 新旧 PDF 反馈关系 | 已确认方向 | 用户生成 PDF 新版本后，旧反馈默认继续绑定原 PDF 版本；用户可以选择是否关联或复制到新版本 | 保留版本语境，同时给予用户自由整理权 |
| D-073 | 进入研究项目 | 已确认方向 | Idea 达到“可研究的 RQ”成熟度后获得进入正式 Research Project 的资格，但是否进入、何时进入由用户自己决定 | 成熟度是资格提示，不是系统强制升级 |
| D-074 | Idea—文献映射 | 已确认方向 | 一个 Idea 可以连接多篇文献，一篇文献也可以连接多个 Idea；连接必须记录文献如何支持、质疑、启发或改变 Idea | Idea 通常比单篇文献更宽，网络表达思考演化而不制造一对一假设 |
| D-075 | 第一版边界 | 已确认方向 | v1 先完成个人版 Idea→RQ→成果 PDF→反馈/反思闭环；团队版只保留角色、权限、协作数据结构等接口 | 先验证个人核心价值，再扩展团队协作 |
| D-076 | 个人数据控制 | 已确认方向 | v1 必须支持用户完整保存、修改和删除自己的 Idea、文献连接、PDF 与反馈记录 | 个人版首先是用户拥有的数据与思考空间 |
| D-077 | v1 核心验收 | 已确认方向 | v1 不以生成 RQ PDF 作为唯一验收；用户还必须能够回到自己的假设，重新检查、修正或确认它 | 产品验证的是可循环的研究思考，而非一次性文案生成 |
| D-078 | 团队合作原则 | 已确认方向 | 团队版采用非上位者合作模式，不预设导师/PI 对 RA/学生的等级控制；具体合作权限后续定义 | P-Layer 支持协作，不复制学阀式权力结构 |
| D-079 | v1 假设重新检测 | 已确认方向 | v1 的重新检测先指重新检查假设的逻辑、前提、文献和证据方向，不要求完成真实数据实验 | 控制第一版范围，保留研究循环的核心价值 |
| D-080 | Idea/RQ 版本 | 已确认方向 | 用户重新检测并修改假设后形成新版本并保留旧版本，例如 `Idea-10 / V5` | 让研究思考可以回看、比较和继续发展 |
| D-081 | 团队权限 | 已确认方向 | 团队成员可以拥有不同的查看、编辑、评论、邀请等操作权限，但权限差异不代表成员之间存在学术等级关系 | 区分协作治理与上位者权力结构 |
| D-082 | 登录鼓励语 | 已确认方向 | 用户每次登录都可以看到一句鼓励自己的话；内容优先来自用户自身的好奇、成果和研究轨迹，而不是泛泛名言 | 建立温和的研究仪式感，让用户感到自己的努力被看见 |
| D-083 | 鼓励语内容来源 | 已确认方向 | 登录鼓励语由名人名言与 Pia! 根据用户状态生成的话混合组成 | 兼具思想传统与个人陪伴感 |
