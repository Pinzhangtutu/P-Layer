## 二、开发目标

只实现个人版核心闭环：

```text
Idea
→ 头脑风暴
→ 初步 Research Question
→ 生成可分享 PDF
→ 反馈与反思
→ 重新检查假设
→ Idea/RQ 新版本
```

用户可以从一个完全模糊的想法开始，例如：

> 为什么风浪越大鱼越贵？是不是因为卖鱼的人少了？

## 三、核心产品原则

Pia! 是教练，不是代写者：

- 帮助用户澄清、追问、示范和发现逻辑问题；
- 不替用户决定理论、假设、研究价值或最终方向；
- 用户可以不同意、跳过、修改、删除、暂停或重新开始；
- Pia! 生成的内容写入正式研究记录前，必须经过用户确认；
- 不把成熟度等级变成天赋评分；
- 不把用户的观察直接改写成因果结论。

## 四、必须实现的功能

### 1. Idea 记录

用户必须可以：

- 创建 Idea；
- 保存原始内容；
- 修改和删除 Idea；
- 查看 Idea 的当前状态；
- 暂停、继续和重新开始探索。

### 2. 头脑风暴路径

支持以下研究思考成果：

```text
模糊 Idea
→ 观察现象
→ 初步命题
→ 可能解释
→ 预测
→ 前提与边界
→ 替代解释
→ 证据方向
→ 初步 RQ
→ 重新检查假设
```

每一步都要有：

- 用户输入区域；
- 保存能力；
- 明确的阶段成果；
- 返回和修改能力；
- Pia! 的可选帮助；
- 不自动把 AI 建议写进用户正式记录。

用户不需要按照固定线性顺序完成，可以返回前一步重新思考。

科学环必须是真实可交互的：用户点击任意节点后，科学环沿最短方向平滑旋转，把该节点带到最高点；该节点放大、提亮并显示简短说明，然后进入对应功能空间。建议将“旋转聚焦”和“进入页面”分成两个短阶段，用户点击明确入口后再进入，避免无提示跳转。动画不能修改 Idea 数据或研究状态。

科学环需要表现理论研究层与实证研究层的关系。P-Layer 当前主要实现实证研究执行，但不能删除理论层；理论可以产生假设，经验概括可以推动理论修正，实证结果也可以回到理论层重新解释。两层不是价值等级，也不是两个孤立产品。四个固定节点为：经验观察、理论与概念、假设与预测、证据与修正。用户可从任意节点进入同一个 Idea，直接聚焦到对应步骤，进入后继续完成至少半圈形成局部闭环。科学环中心的主要动作应是“输入我的 Idea”，用于创建或开始新的研究想法；已有 Idea 的查看和继续探索放在首页或次级入口。

视觉上将理论研究层与实证研究层左右分列，建议左侧理论、右侧实证，并用循环箭头表示理论推演进入经验检验、证据再回到理论修正。v1 理论侧只支持概念、理论、命题和逻辑推演的记录与连接，不实现独立理论研究流程。用户从任意节点进入后，Pia! 可以显示建议继续的两个节点，但用户可以随时离开、暂停、返回或选择其他路径。

用户完成当前理论或实证轨道后，Pia! 提示是否愿意继续另一条轨道；用户可以继续，也可以保存当前成果并离开。完成一条轨道只是阶段性研究成果，不等于一篇论文已经完成。科学环需要显示当前 Idea 已经走过的节点和当前所在节点。

理论记录与实证记录默认归属于同一个 Idea，用户未来可以主动拆分为两个新 Idea。只完成理论轨道时，也可以生成“理论研究构想”PDF，不要求先完成实证轨道。用户只进入一条轨道时，不显示另一条轨道进度；只有用户主动同时探索两条轨道时，才显示双轨进度。

只有当用户点击并进入另一条轨道后，才算同时进入两条轨道，从这一刻开始显示双轨进度。RQ 阶段的理论研究构想 PDF 应包含核心概念、理论依据、命题、逻辑推演和待验证问题。理论轨道和实证轨道都完成一部分后，允许用户选择生成合并两条轨道的“综合研究构想”PDF，但默认不要求合并。两条轨道通常具有不同目的、读者和表达方式。

同一个 Idea 下，理论轨道和实证轨道可以分别形成各自的 RQ；它们不要求共享同一个 RQ。一个 Idea 是较宽的思考来源，可以分支出多个研究问题，系统不应强迫它们压缩成一个 RQ。

RQ 采用 Idea 下的分支编号，例如 `Idea-10 / RQ-1`、`Idea-10 / RQ-2`。理论 RQ 与实证 RQ 都可以各自生成独立的成果 PDF。某个 RQ 进入正式研究项目后，其他 RQ 是否继续留在原 Idea 下独立发展，由用户选择；系统不自动关闭、合并或迁移其他 RQ。支持分层版本编号，例如 `Idea-10 / V5 / RQ-2 / V3`。RQ 拆分为新 Idea 时保留“源自 Idea-10 / RQ-2”的溯源关系。

RQ 采用 Idea 下的分支编号，例如 `Idea-10 / RQ-1`、`Idea-10 / RQ-2`。理论 RQ 与实证 RQ 都可以各自生成独立的成果 PDF。某个 RQ 进入正式研究项目后，其他 RQ 是否继续留在原 Idea 下独立发展，由用户选择；系统不自动关闭、合并或迁移其他 RQ。

### 3. RQ 形成与出口

当用户形成可研究的 RQ 后，不要自动跳转到正式项目。用户可以自行选择：

- 生成成果 PDF；
- 继续连接文献；
- 请求反馈；
- 重新检查假设；
- 导入正式研究项目；
- 暂停。

### 4. 版本系统

用户修改命题、预测、假设或 RQ 后，必须能够生成新版本，并保留旧版本。

版本示例：

```text
Idea-10 / V1
Idea-10 / V2
Idea-10 / V3
Idea-10 / V5
```

必须支持：

- 查看历史版本；
- 比较修改前后；
- 恢复历史版本；
- 不自动覆盖旧版本。

### 5. PDF 成果

用户可以生成只展示自己成果的可分享 PDF，包括：

- 原始观察；
- 初步命题；
- 可能解释；
- 预测；
- 前提与边界；
- 替代解释；
- 证据方向；
- 初步 RQ；
- 用户姓名/昵称；
- 生成日期；
- PDF 版本号。

PDF 不应展示：

- Pia! 的提问；
- Pia! 的建议；
- 成熟度判断；
- AI 生成痕迹；
- 用户的私密错误记录。

### 6. 反馈与反思

如果当前系统已有反馈功能，请与 PDF 版本连接；如果没有，先实现合理的数据接口。

基本要求：

- 反馈绑定具体 PDF 版本；
- 反馈包含类型和自由文字；
- 一条反馈可以有多个类型；
- Pia! 可以归纳反馈，但不替用户决定是否采纳；
- 用户确认后，反馈反思才能保存到 Idea；
- 用户可以把反馈归档为原 Idea 的修改记录，或主动转为新 Idea；
- 旧反馈默认不自动迁移到新 PDF 版本。

### 7. 重新检查假设

v1 的“重新检查假设”指重新检查：

- 逻辑；
- 前提；
- 文献依据；
- 证据方向。

不要求 v1 完成真实实验、数据收集或统计检验。

## 五、页面导航

目标导航：

```text
首页｜科学环｜项目管理｜看板｜设置
```

现有九步项目开发流程要保留，但它属于正式研究项目内部，不应成为新用户的默认起点。
