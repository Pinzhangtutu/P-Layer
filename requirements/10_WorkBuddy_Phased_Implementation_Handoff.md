## 1. 产品核心定位

P-Layer 帮助一个原本没有科研资源的人，把好奇、生活观察、文献怀疑或工作发现逐步发展为 Research Question。

Pia! 是教练，不是代写者：

- 帮助用户澄清、追问、示范和发现逻辑问题；
- 不替用户决定理论、假设、研究价值或最终方向；
- 用户可以不同意、跳过、修改、删除、暂停或重新开始；
- AI 生成内容写入正式研究记录前必须由用户确认。

## 2. v1 目标闭环

v1 先完成个人版核心闭环：

```text
登录
→ 科学环
→ 头脑风暴或文献网络
→ Idea 逐步形成 RQ
→ 生成可分享 PDF
→ 接收/归纳反馈
→ 重新检查假设
→ 形成新的 Idea/RQ 版本
```

v1 不要求完成真实实验、数据收集、统计检验或团队协作。

这里的“重新检查假设”是指重新检查逻辑、前提、文献和证据方向，并允许用户修正或确认假设。

## 3. 顶部导航改造

### 现有结构

```text
首页｜头脑风暴｜项目开发｜看板｜项目管理｜文献管理｜设置
```

### 目标结构

```text
首页｜科学环｜项目管理｜看板｜设置
```

### 功能映射

| 入口 | v1 职责 |
|---|---|
| 首页 | 用户登录后的个人状态页 |
| 科学环 | P-Layer 的核心研究思考入口 |
| 项目管理 | 管理已经成立的正式 Research Project |
| 看板 | 管理研究行动和任务进度 |
| 设置 | 账户、Pia!、模型、本地数据和偏好 |

“头脑风暴”和“文献管理”不再作为顶部一级导航，改为科学环内部的两个核心入口。如果当前代码兼容成本过高，可以暂时保留旧入口，但必须让科学环成为首页/主入口逻辑，而不是让用户默认从项目执行开始。

## 4. 分步开发顺序

### 第一步：检查与保护现有功能

1. 检查项目启动方式和实际运行端口；
2. 检查当前路由、页面、数据库和数据模型；
3. 找出首页、头脑风暴、项目开发、项目管理、看板、文献管理和设置的现有实现；
4. 确认现有 Idea 数据不会因导航改造丢失；
5. 先报告拟修改文件和风险，再进入实现。

### 第二步：重组导航和页面关系

实现目标导航：

```text
首页｜科学环｜项目管理｜看板｜设置
```

要求：

- 首页和科学环不能显示完全相同的内容；
- 旧的九步项目流程保留在正式研究项目内部；
- 不让新用户打开软件就默认进入“研究问题/变量/实验”流程；
- 保持已有功能可访问，不进行破坏性删除。

### 第三步：实现首页“我的研究空间”

首页回答：

> 我最近在做什么？我可以继续什么？

建议包含：

- 登录鼓励语；
- 最近打开的 Idea；
- 最近连接的文献；
- 待处理反馈；
- 最近生成的 PDF；
- “继续上一次探索”；
- 进入科学环的主按钮。

首页不展示完整科学环，也不展示九步项目执行清单。

### 第四步：实现科学环主页面

科学环回答：

> 一个研究想法如何在观察、理论、预测和证据之间发展？

页面应提供四个研究位置：

- 经验观察：我看见了什么？
- 理论与概念：我如何理解它？
- 假设与预测：如果它成立呢？
- 证据与修正：我如何知道？

中心显示用户自己的研究想法，例如：

```text
我的 Idea
```

用户可以从任意位置进入，不能被强迫按线性顺序完成。

科学环内部至少提供三个入口：

1. 我的头脑风暴；
2. 我的文献网络；
3. 继续上一次探索。

### 第五步：连接头脑风暴功能

头脑风暴的黄金路径：

```text
模糊 Idea
→ 观察现象
→ 初步命题
→ 可能解释
→ 预测
→ 前提与边界
→ 替代解释
→ 证据方向
→ 初步 RQ
→ 重新检查假设
```

每一步都需要：

- 用户输入区域；
- 保存按钮；
- 当前步骤成果；
- 返回和修改能力；
- Pia! 的可选帮助；
- 不把 Pia! 建议自动写入正式记录。

黄金测试内容：

```text
为什么风浪越大鱼越贵？是不是因为卖鱼的人少了？
```

最终至少应形成一个清楚、可继续研究的初步 RQ，而不是由系统直接替用户生成确定答案。

### 第六步：连接文献网络

文献关系必须支持一对多和多对多：

- 一个 Idea 连接多篇文献；
- 一篇文献连接多个 Idea；
- 文献可以连接 Idea 的整体、命题、预测或 RQ；
- 文献连接必须能够记录“支持、质疑、启发、理论、测量、方法、边界、改变想法”等关系。

文献相似关系与“文献如何改变我的 Idea”必须区分。

### 第七步：实现版本和重新检查

用户修改假设、命题或 RQ 后，应可以形成新版本并保留旧版本，例如：

```text
Idea-10 / V1
Idea-10 / V2
Idea-10 / V3
Idea-10 / V5
```

要求：

- 用户可以查看历史版本；
- 用户可以比较修改前后；
- 用户可以恢复历史版本；
- 系统不能自动覆盖旧版本；
- 用户自己决定什么时候进入正式研究项目。

### 第八步：实现 PDF 出口

用户形成初步 RQ 后，可以自行选择：

- 生成成果 PDF；
- 继续连接文献；
- 请求反馈；
- 重新检查假设；
- 导入正式研究项目；
- 暂停。

PDF 只展示用户自己的成果，不展示 Pia! 的提问、建议、成熟度判断或 AI 痕迹。

## 5. 登录鼓励语

登录时展示一句鼓励语，内容由两类混合组成：

- 名人名言；
- Pia! 原创话语。

比例随用户参与程度变化：

- 初期：名言较多；
- 用户形成研究轨迹后：Pia! 内容逐步增加；
- 稳定使用后：大致各占一半。

界面只显示作者，不显示来源说明或 Pia! 生成理由。名人名言在内容库内部必须区分已核实来源、常见归属但存疑和来源不明，不能把存疑引语当作确定署名。

用户不能切换只看名言或只看 Pia!，保持混合体验。

## 6. 页面美学

推荐采用混合方案：

- 信息结构使用“安静学术工作台”：雾蓝、白色、深靛蓝、细线、清晰层级；
- 入口表达使用“温暖科学旅程”：米白、青绿色、少量珊瑚橙、具有邀请感的卡片；
- 页面应该可信但不冷漠；
- 不使用游戏化分数、排行榜或夸张成就徽章。

## 7. 个人数据控制

v1 必须支持用户对自己的以下内容进行保存、修改和删除：

- Idea；
- Idea 版本；
- 文献连接；
- PDF；
- 反馈；
- 反馈反思。

删除、修改和重新开始是用户的自由。与此同时，Idea 版本历史需要保留，确保用户能够回看和恢复。

## 8. 反馈边界

如果现有系统已有反馈能力，按以下原则连接；如果没有，v1 可以先实现最小接口：

- 反馈绑定具体 PDF 版本；
- 反馈者可以选择姓名/昵称或匿名；
- 反馈包含类型和自由文字；
- 一条反馈可以属于多个类型；
- Pia! 可以归纳反馈，但不替用户采纳；
- 用户确认后，反馈反思才能保存到 Idea；
- 用户可以选择归档到原 Idea 或转为新 Idea；
- 旧反馈默认不自动迁移到新 PDF 版本。

## 9. 团队版接口

v1 不实现完整团队协作，但不要把未来结构锁死。

未来团队版允许：

- 成员之间没有预设的导师/学生等级；
- 角色和操作权限可以不同；
- 可以配置查看、编辑、评论、邀请等权限；
- 权限差异不代表学术等级关系。

## 10. v1 验收标准

### 必须通过

1. 用户登录后首先理解 P-Layer 是从好奇开始的研究空间；
2. 用户可以从科学环进入头脑风暴或文献网络；
3. 用户可以保存、修改和删除个人 Idea；
4. 用户可以逐步形成命题、预测、边界、替代解释和证据方向；
5. 用户可以形成并保存初步 RQ；
6. 用户可以回到假设并重新检查；
7. 修改后可以生成新版本并保留旧版本；
8. 用户可以生成只展示自己成果的 PDF；
9. 用户可以自行选择下一步，而不是被自动导入项目；
10. 现有正式研究项目的九步流程仍然可访问。

### 暂不要求

- 真实实验执行；
- 数据收集；
- 统计检验；
- 完整团队协作；
- 邮箱自动读取；
- 自动文献发现；
- 完整通知系统；
- 论文全文生成。
